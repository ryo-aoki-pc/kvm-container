# qemu-kvm コンテナ (AlmaLinux 10)

qemu-kvm / libvirt / virt-viewer を 2 つの systemd コンテナ (`kvm` = サーバ、`kvm-gui` = デスクトップ側) に収め、
qemu も libvirt も入れていない軽量なホストで VM を動かして、その画面をホストのデスクトップ (GNOME Wayland) に表示する。
VM の作成・操作はコマンドライン (`./kvm.sh virt-install` / `./kvm.sh virsh`)、画面は virt-viewer (`./kvm.sh viewer`)。ブラウザや Web コンソールは使わない。
手順書は導入・VM の作成・利用・再ログイン後のシナリオと、変更後の確認を番号付きリストで載せている。検証結果は [検証記録](docs/verification/setup.md)、背景や実装の説明は [参照情報](docs/reference/setup.md) に分けている。
実装の仕様 (CLI・環境変数・マウント・起動/停止シーケンス・不変条件、図付き) は [docs/SPEC.md](docs/SPEC.md)、変更時の注意は [CLAUDE.md](CLAUDE.md)。

## 手順書

- 手順書は [docs/setup.md](docs/setup.md) の 1 本。`## 実施手順` の下で、1 度だけ行うシナリオ (導入する、VM を作る) と繰り返すシナリオ (VM を使う、再ログインしたとき) を見出しで分けてある。ブリッジは任意の節
- 初めてなら、導入する → VM を作る → VM を使う の順に上から貼る。以後は、必要なシナリオだけを貼る
- 対象は AlmaLinux 10.2 (物理 GNOME / ディスプレイ無し)。検証範囲 (どの節を本実行したか) は、[検証記録の対象と検証環境](docs/verification/setup.md#対象と検証環境)の「状態」に書いてある

| 節 | 頻度 | 用途 | 使うサブコマンド |
|---|---|---|---|
| [導入する](docs/setup.md#導入する-1-度だけ) | 1 度だけ | podman と git だけのホストにこのリポジトリを clone し、イメージをビルドしてコンテナを起動する | `build` / `up` |
| [VM を作る](docs/setup.md#vm-を作る-vm-ごとに-1-度) | VM ごとに 1 度 | x86_64 のホストで、`virt-install` で VM (ディスクは SATA の SSD、NIC は e1000e) を作り、virt-viewer の画面でインストールして、自動起動を設定する | `virt-install` / `viewer` / `virsh` |
| [VM を使う](docs/setup.md#vm-を使う-繰り返し) | 繰り返し | コンテナと VM を起動し、virt-viewer で画面を見て、`virsh` で止める。ホストを止める前は `down` | `up` / `virsh` / `viewer` / `down` |
| [再ログインしたとき](docs/setup.md#再ログインしたとき-繰り返し) | 繰り返し | 再ログイン後に `kvm-gui` だけを作り直す (VM は動いたまま) | `up gui` |
| [VM をホストのブリッジにつなぐ (任意)](docs/setup.md#vm-をホストのブリッジにつなぐ-任意) | 任意、1 度だけ | VM にホストと同じセグメントの IP を割り当てる (NetworkManager のブリッジ) | `KVM_BRIDGE=… ./kvm.sh up` |
| [VM を削除する](docs/setup.md#vm-を削除する) | VM ごとに 1 度 | VM の定義・UEFI 変数・ディスクを消す (ISO は残る) | `virsh undefine` |
| [更新](docs/setup.md#更新) | 更新のたび | リポジトリを最新にし、イメージを作り直して起動し直す | `down` / `build` / `up` |
| [ロールバック](docs/setup.md#ロールバック) | 戻すとき | 任意の節を戻し、コンテナ・`data/`・イメージを消す | `down` / `clean` |

## 記法

- 手順書は [docs/setup.md](docs/setup.md) の 1 本。タイトル直後の `## 実施手順` の下に、シナリオごとの見出しを置く。見出しの末尾には頻度 (「(1 度だけ)」「(VM ごとに 1 度)」「(繰り返し)」) を付ける
- シナリオの中は、変数設定、コマンド、動作確認を番号付きリストで並べる (マーカーはすべて `1.` の自動採番。番号付きの見出しは使わない)。任意の節 (見出しの末尾に「(任意)」)・使い方の基本・VM を削除する・更新・ロールバックはその後ろの見出しに置き、中の手順も番号付きリストにする
- 手順の番号はシナリオ・節ごとに 1 から数える。ほかのシナリオの手順は「導入の手順 1」「VM 作成の手順 3」「VM 利用の手順 2」「再ログインの手順 1」、同じシナリオ・節の中では「この節の手順 N」と呼ぶ
- 各手順は「1 行の説明 (太字にしない 1 文、60 字まで) → コマンドのブロック → 確認点の箇条書き」の順に書く。実行に必要な前提・分岐・待機条件・注意・期待結果は手順に残し、実測や検証履歴は検証記録、選定理由・仕様の説明は参照情報に置く
- 任意の節は `## 実施手順` のリードから案内する (途中に挟むブリッジの節は「導入の後に…」と書く)。任意の節を元に戻す手順は、ロールバックの「〜の節を通したときだけ、」の手順にまとめる
- 条件付きの手順は、条件を 1 行の説明に書く (「〜ときだけ、」)。判定する手順に「〜なら、この節の手順 N は飛ばす」と書く
- 環境固有の値 (clone 先 `REPO`、ISO のパス、VM 名と VM のネットワーク) は導入の手順 1 の変数ブロックで一度だけ設定する。繰り返すシナリオは、新しいシェルで導入の手順 1 を貼り直してから始める。任意の節だけで使う値 (ブリッジの NIC 名) は、その節の手順 1 で設定する
- 変更が必須の変数は 1 変数ずつのコードブロック (説明は「変数を設定する (`ISO` は必ず値を入れる)。」)、変更が任意の変数は 1 つのブロックにまとめて末尾で読み戻す。読者が値を入れるブロックは `${VAR:?...}` で、空のまま貼ると中断する。変える必要の無い値 (clone 元の URL など) は変数にせず、コマンドに直接書く
- 新しいシェルで貼り直す変数のブロックには、読み戻しのほかに、導入の手順 1 の最後の `cd` (リポジトリ直下へ移る) しか置かない。値の確認は次の手順に置く
- `kvm.sh` 自身が読む環境変数 (`KVM_HOST` / `KVM_BRIDGE` / `TZ`) は導入の手順 1 の変数ではなく、`KVM_BRIDGE=br0 ./kvm.sh up` のようにコマンドの前に付ける。一覧は[参照情報の環境変数](docs/reference/setup.md#環境変数)
- `./kvm.sh` はリポジトリの中で一般ユーザーとして実行する (`sudo` は付けない。内部で `sudo podman` を呼ぶ)
- 上から順にコードブロックを貼れば通るようにする。リポジトリの clone も手順に含め、画面の有無などの分岐は読者に選ばせずブロックの中で判定する。手順書はホストの `sudo` がパスワードを聞かない前提で書き (sudoers の設定は読者の責任。書き方は載せない)、手順を分けるのは完了待ち・対話入力 (`[y/N]`)・ssh の切断・ウィンドウが開く、など sudo 以外の理由があるときだけにする。止める手順の最後には「次の手順は〜してから貼る」と書く
- 実行の前提 (実行するユーザーと端末、ホストの sudo、対話入力のある手順、別の場所で行う手順) は `## 実施手順` の冒頭に `> [!IMPORTANT]` で示す。本実行していない範囲は検証記録に示す
- アラートは本文の最上位にだけ置き (GitHub は番号付きリストや折り畳みの中のアラートを描画しない)、1 文書 5 個までにする (`[!TIP]` は使わない)。手順の中の注意は太字の箇条書きにし、取り戻せない削除をする手順のある節では、そのリードに `> [!CAUTION]` を置いて手順を名指しする
- 箇条書きは 1 項目に 1 つの事実で、末尾に「。」を付けない。150 字を超える段落は箇条書きに割る
- 出力例・表の中の値は `<VM名>` / `<uid>` などのプレースホルダで書く。`<...>` を含むコマンドは bash のコードブロックに置かない
- 説明が [docs/SPEC.md](docs/SPEC.md) にある事項は手順書で繰り返さず、節番号で参照する
- コマンドを変更したときは検証記録に対象版・実施内容・未確認事項を記し、実行していない行を検証済みとは扱わない。過去の検証範囲は手順書に載せない
- 変更後の回帰確認は手順書の[変更後に確認する](docs/setup.md#変更後に確認する)を手で流す (物理 GNOME / ディスプレイ無し / VM のライフサイクル)。期待結果の表は [docs/SPEC.md 9 章](docs/SPEC.md#9-検証手順)
- ドキュメントとコミットメッセージは日本語、コード内のコメントと `kvm.sh` の実行時メッセージは英語
- パスワード、鍵、トークンなどの秘密情報は残さない (コンテナにはホストのパスワードもハッシュも渡していない)
